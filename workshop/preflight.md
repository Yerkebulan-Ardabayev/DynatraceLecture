# Пре-флайт перед каждой лекцией (10-15 минут)

Запускать вечером накануне и повторить коротко за час до лекции. Ничего нового не изобретаем: чек-лист собирает уже существующие механизмы курса (docs_freshness, drift_report, quality_check) и добавляет ручной прогон демо завтрашнего дня.

Для шага 2 нужна сохранённая сессия (`state/storage_state.json`). Если её нет или она протухла:

```bash
cd ~/Desktop/Projects/dt-crawler && python auth.py --manual
```

- Если по теме завтрашнего дня есть дрейф: открыть указанную страницу `docs.dynatrace.com/managed/...`, сверить тезис в `day-N.md`, поправить сценарий до лекции (не после).

## 3. Ручной прогон демо завтрашнего дня (главный шаг)

Открыть завтрашний `workshop/day-N.md` и пройти НА ЖИВОМ тенанте:

1. Каждый блок «Демо»: маршрут открывается, данные на месте, объект демо жив.
2. Каждый блок «Как найти»: пройти путь кликов от главного меню буквально по написанному. Каждый пункт меню должен называться ТАК, как в сценарии, вплоть до регистра. После обновления кластера пункты переезжают и переименовываются: любое расхождение = правка сценария сегодня.
3. Все места «(не сверено)» в завтрашнем дне: попытаться сверить и снять пометку либо подготовить фолбэк.

## 4. Что делать при расхождении (приоритет действий)

1. **Правка сценария**: переименовался пункт/кнопка, переехал маршрут: обновить `day-N.md` сейчас (и пометку «(не сверено)» снять или обновить).
2. **Замена объекта демо**: умер сервис/проблема/сессия: выбрать соседний живой объект того же типа, вписать имя в заметку лектора.
3. **Фолбэк-скриншот**: экран недоступен (права, 403, пустые данные): взять captured-скриншот из `output/screenshots/<day>/<topic>/…` и показать его с честной оговоркой.
4. **«Показать словами»**: ничего из выше не сработало: словесная заглушка по протоколу сбоев (`teaching_model.md` §6): описать, как выглядел бы экран, пообещать вернуться, идти дальше. Пометить в сценарии, чтобы починить к следующему разу.

## 5. Зоны частого дрейфа (сверять при каждом обновлении кластера/тенанта)

| Зона | Что дрейфует | Где сверять |
|---|---|---|
| Левое меню Classic | названия групп и пунктов, новые SaaS-баннеры (каждый релиз Dynatrace) | живой тенант + все пути «Как найти» |
| Metric events / Alerting | экран событий метрик переезжает в новые UI, баннер «Try the new custom alerts» | docs.dynatrace.com/managed/ раздел Anomaly detection |
| Session Replay / Sessions | баннеры «Users & Sessions app», настройки захвата | managed-дока RUM + Settings приложения |
| Synthetic | права/403, состав настроек outage handling | managed-дока Synthetic + /ui/synthetic |
| SLO | экран списка и мастер создания | managed-дока SLO |
| Hub / Extensions | баннеры, EOL-предупреждения (пример: Python EOL в Hub) | /ui/hub живьём |
| Лимиты и retention в тезисах | значения в managed-доке меняются между версиями | freshness_report + конкретные /managed/-страницы тем |
| AppSec | счётчики и экраны уязвимостей | Security Overview живьём |

## 6. После обновления кластера (Managed у клиента) или крупного релиза тенанта

Полный прогон ВСЕХ путей «Как найти» всех четырёх дней (не только завтрашнего): пункты меню переезжают пакетно. Затем `python scripts/drift_report.py` без лимита и правка сценариев одним заходом.
