## ГДЕ
Два экрана тенанта. Список баз: Application Observability → Database Services, route `/ui/databases`.
Пороги аномалий: Settings → Anomaly detection → Database services, route `/ui/settings/builtin:anomaly-detection.databases`.

## ЗАЧЕМ
Мониторинг БД клиентский: OneAgent перехватывает каждый SQL через драйвер приложения (JDBC/ODBC), а не через админский доступ к самой базе.
Отвечает на «где узкое место, в самой базе или в запросе приложения» и «какой SQL нагружает БД». Это клиентская перспектива, не инвентарь инфраструктуры: в списке только базы, с которыми работал хотя бы один инструментированный клиент.

## ЦИФРЫ
- Список баз на снимке темы: заголовок 30 Databases (у вашего тенанта цифры могут быть другими).
- Timeframe по умолчанию: Last 2 hours, список зависит от него и от фильтров слева.
- Reference period для baseline БД: past 7 days, Davis учитывает время суток и день недели.
- TradeManagement на демо: медиана 2.09 ms, Slowest 10% 10.1 ms, 0% ошибок, 248 запросов в минуту.
- Slowest 10%: время отклика верхних 10% запросов, отдельная колонка и отдельный порог аномалий.
- Oracle Database Insights опрашивает БД с Environment ActiveGate, доступен начиная с версии 1.173.

## ЕСЛИ→ТО
- ЕСЛИ базой не пользовался ни один инструментированный клиент → её нет в списке `/ui/databases`: это клиентская перспектива, не инвентарь инфраструктуры.
- ЕСЛИ за Reference period (past 7 days) прошла миграция, новый индекс или резкая смена нагрузки → baseline несколько дней ложно срабатывает, пока модель пересчитается; Reference period можно сбросить и перенабрать заново.
- ЕСЛИ клиент не может подключиться (Connection refused, Authentication failed, timeout) → драйвер бросает исключение, OneAgent пишет Failed connect, и при превышении порога за минуту Davis создаёт Problem раньше, чем по времени отклика.
- ЕСЛИ ночной cron ходит в БД на чистом psql без OneAgent → его запросы не видны: обернуть в Python/Java с OneAgent либо снимать через Extensions с прямым опросом БД.

## ЗАПАСНОЙ ПЛАН
Если список `/ui/databases` пуст: проверяю timeframe (по умолчанию Last 2 hours) и снимаю фильтры слева, показываю снимок темы (заголовок 30 Databases на демо) и разбираю колонки Response time median, Slowest 10%, Failure rate, Requests.
На странице аномалий вживую виден только заголовок Reference period, остальные блоки свёрнуты: проговариваю их по смыслу (Response time, Failure rate, Database failed connects, Load drops/spikes), конкретные дефолтные пороги по памяти не называю, значения на самой странице тенанта authoritative.
Если на демо нет write-прав: показываю снимок и говорю, что переопределение для конкретной БД делается в её карточке → Settings, а глобальная страница задаёт дефолт.

## ВОПРОСЫ АУДИТОРИИ
- «Чем Database Service отличается от Database Host?» Ответ: Service это БД глазами клиента через драйвер (время ответа на запрос), Host это хост с процессом БД (CPU, Memory, Disk I/O); связаны через Smartscape, но сущности разные, список `/ui/databases` показывает именно Services.
- «Мониторинг БД открывает новые каналы наружу в закрытом контуре?» Ответ: нет, всё локально (OneAgent → ActiveGate → кластер, данные внутри кластера), исключение только Oracle Database Insights, который опрашивает БД с Environment ActiveGate внутренним каналом (доступен с версии 1.173) и за пределы контура не выходит.
- «Какой запрос Dynatrace считает самым медленным в Top Database Statements?» Ответ: топ строится по метрикам Response time, Fetch count и Row count; редкий тяжёлый и частый лёгкий запросы нагружают БД по-разному, поэтому смотреть и на время отклика, и на частоту вызовов.
