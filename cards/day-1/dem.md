## ГДЕ
Два живых экрана. Список приложений: Application Observability → Frontend → Applications, route `/ui/applications` (наполненный экран живёт на легаси-хеше `#uemapplications`, `/ui/applications` часто пустая оболочка).
Сессии: Frontend → User sessions, route `/ui/user-sessions`.

## ЗАЧЕМ
DEM это взгляд со стороны пользователя: RUM (реальные люди), Mobile RUM, Synthetic (роботы по расписанию).
Отвечает на «медленно у нас или у клиента» и «на клиенте, в сети или на бэкенде».

## ЦИФРЫ
- Applications на снимке темы: 24 приложения (у вашего тенанта цифры могут быть другими).
- User sessions по умолчанию: первые 100 сессий, период задаётся селектором справа сверху.
- Apdex: одно число от 0 до 1, шкала из 5 уровней (Excellent 0.94-1.0 / Good 0.85-0.94 / Fair 0.7-0.85 / Poor 0.5-0.7 / Unacceptable <0.5).
- User experience score сессии считается из весов: User action 3, Error 1, Rage event 2, Crash 5000.
- RUM-сессии в Classic хранятся 35 дней.

## ЕСЛИ→ТО
- ЕСЛИ OneAgent на web-tier не установлен → RUM-сниппет не внедряется, приложения в списке нет вообще.
- ЕСЛИ OneAgent есть, но приложение в Settings → Web and mobile monitoring не создано → сниппет работает «в никуда», данные не привязываются к карточке.
- ЕСЛИ в сессии есть хотя бы одно Frustrating-действие → сессия максимум Tolerable, Satisfying уже не станет.
- ЕСЛИ выставить фильтр User experience score = Frustrating → в таблице остаются только проблемные сессии (краш, ошибки, цепочка медленных действий), быстрый вход в разбор.

## ЗАПАСНОЙ ПЛАН
Экран приложений пуст или `/ui/applications` отдаёт пустую оболочку: открываю наполненный список через `#uemapplications`, показываю снимок из курса.
По снимку проговариваю заголовок с числом приложений, колонку Performance с рейтингом Apdex, панель фильтров слева.
Если список сессий пуст: показываю снимок User sessions из курса и разбираю пример фильтрации (Browser Safari + Operating system iOS + Errors and annoyances).

## ВОПРОСЫ АУДИТОРИИ
- «Чем приложение отличается от сервиса?» Ответ: приложение это frontend в браузере или мобильном (домен плюс RUM), сервис это backend-процесс на хосте; связывает их заголовок x-dynatrace на XHR-запросе.
- «Карточка приложения есть, а сессий ноль, почему?» Ответ: Content-Security-Policy блокирует beacon или домен ActiveGate недоступен из сети пользователей.
- «Как в закрытом контуре собирать RUM с внешних клиентов?» Ответ: ActiveGate в DMZ с публичным доменом либо reverse-proxy, принимающий RUM-трафик снаружи и проксирующий во внутренний ActiveGate.
