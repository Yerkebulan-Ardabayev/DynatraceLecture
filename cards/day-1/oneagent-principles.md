## ГДЕ
Settings → Preferences → OneAgent features; Settings → Processes and containers → Process group monitoring и Built-in process monitoring rules.
Routes (`/ui/settings/`): builtin:oneagent.features, builtin:process.process-monitoring, builtin:process.built-in-process-monitoring-rule.

## ЗАЧЕМ
Показываем, как агент решает, что инструментировать: фичи-сенсоры, главный тумблер deep monitoring, правила распознавания процессов.
Без этого технология на хосте остаётся невидимой или отображается как generic, без специфических метрик.

## ЦИФРЫ
- Список фич длинный: на снимке темы пагинация до 18-й страницы; по умолчанию включён только базовый набор, остальное Opt-In.
- Режим и лицензия: Full-Stack 16 GiB → 1 HU, Infrastructure mode 0.3 HU.
- Go: автоматическая инструментация 64-битных бинарей на x86 и ARM64; Ruby: без нативного агента, телеметрия через OpenTelemetry SDK по OTLP.

## ЕСЛИ→ТО
- ЕСЛИ нужный сенсор выключен → технология на хосте невидима: процесс работает, но трейсов и специфичных метрик нет; включить лишнее → избыточная нагрузка агента.
- ЕСЛИ Min. OneAgent version выше сборки парка → тумблер нажимается, но фича молчит, пока админ не перенесёт пакет OneAgent через CMC и парк не обновится.
- ЕСЛИ выключить Enable automatic deep monitoring → метрики ОС и процессов собираются, но PurePath не строятся, код не инструментируется.

## ЗАПАСНОЙ ПЛАН
Экран не открылся или список выглядит иначе: показываю снимок из курса.
По снимку проговариваю колонки (Enabled, Summary, Min. OneAgent version, Details) и три категории фич: сенсоры кода, платформы и сервисы, подсистемы.
Конкретную фичу вживую не ищу листанием: список разбит на страницы, ищу фильтром либо показываю на снимке.

## ВОПРОСЫ АУДИТОРИИ
- «Поставили OneAgent, а трейсов по Java нет. Что проверить первым?» Ответ: перезапускали ли процесс: серверы приложений (Java, .NET) нужно перезапустить после установки агента.
- «Почему не включить все фичи сразу?» Ответ: агент понесёт избыточную нагрузку; по умолчанию активен базовый набор, остальное включают осознанно.
- «Процесс распознался как generic: что делать?» Ответ: включить подходящее встроенное правило либо написать кастомное в Custom process monitoring, у него приоритет выше встроенных.
