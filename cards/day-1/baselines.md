## ГДЕ
Пять страниц Settings → Anomaly detection: Services `/ui/settings/builtin:anomaly-detection.services`, Database services, Hosts (infrastructure-hosts), Holiday-aware baseline, Frequent issue detection.

## ЗАЧЕМ
Davis AI строит baseline (коридор нормы) на каждую сущность отдельно, с учётом сезонности, и ловит выход за коридор как аномалию.
Это заменяет общий статический порог, который бессмысленен, когда сервисы работают на разной скорости.

## ЦИФРЫ
- Три типа порогов: Auto-adaptive (по умолчанию), Static (фиксированное число), Metric events (кастомное правило на Metrics Selector).
- Период обучения baseline: 7 дней для трафика; для error rate и response time пороги активны раньше, после 20% недели (около 1.4 дня).
- Многомерный baseline frontend RUM ведётся по 4 разрезам: user action, geolocation, browser, operating system.
- Страница Hosts самая большая в блоке: правил больше 20.
- Adaptive baseline закрывает около 80% задач; Static ставят поверх для compliance (например CPU выше 85%).
- Точные дефолты порогов (Absolute и Relative) Dynatrace не публикует таблицей: authoritative это значения на самой странице тенанта.

## ЕСЛИ→ТО
- ЕСЛИ тумблер Holiday aware включён → Davis вырезает госпраздники из обучающей выборки; выключен → праздники учитываются как обычные дни и искажают baseline.
- ЕСЛИ метрика это трафик → алерты включаются только после полной недели истории (7 дней); ЕСЛИ error rate или response time → пороги активны уже после 20% недели.
- ЕСЛИ на серверах БД правило High memory usage шумит → его отключают на уровне хост-группы: база штатно занимает всю память под кэш, это норма.
- ЕСЛИ одна и та же проблема повторяется много раз за неделю → Frequent issue detection сворачивает её в одну запись; отключают, если каждый случай должен идти в ITSM отдельным инцидентом.

## ЗАПАСНОЙ ПЛАН
Тумблер Holiday aware на демо серый (нет write-прав): это ожидаемо, показываю снимок и проговариваю, что на боевом окружении админ включает его сразу после развёртывания.
Отдельно проговариваю локальный акцент: казахстанских праздников (Наурыз, День Республики) Dynatrace по умолчанию не знает, их закрывают Maintenance window в режиме тишины.
Если страница дефолтов пуста или серая: не называю конкретные пороги по памяти, отсылаю к значениям на самой странице тенанта.

## ВОПРОСЫ АУДИТОРИИ
- «Чем плох общий порог отклик больше 500 мс?» Ответ: baseline строится на каждый сервис отдельно (100 сервисов это 100 моделей) с учётом сезонности; общий порог бессмысленен для сервиса с 50 мс и для сервиса с 2000 мс одновременно.
- «Dynatrace знает наши праздники?» Ответ: по умолчанию нет (в списке New Year, Easter, Thanksgiving, Black Friday, Christmas); на казахстанские праздники Holiday aware не сработает, закрывают отдельным Maintenance window.
- «Где смотреть дефолтные пороги?» Ответ: на самой странице Settings → Anomaly detection тенанта; единой публичной таблицы дефолтов нет, значения на странице authoritative.
- «Ночной бэкап каждый день грузит диск на полчаса: что сделает baseline через неделю?» Ответ: примет в норму для этого времени суток (модель учитывает время дня и день недели) и будить дежурного перестанет; алерт останется только на отклонения от этого ритма.
