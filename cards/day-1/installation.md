## ГДЕ
Мастер: Manage → Deploy Dynatrace, живой route `/#deploy` (сверено 2026-07-28: заголовок «Deploy Dynatrace», кнопка «Start installation», блок «Install ActiveGate to extend your monitoring»); пункт есть и в Favorites.
Контроль парка: Manage → Deployment Status (`/ui/deploymentstatus`) и Manage → OneAgent Health (`/ui/diagnostictools/healthstate`): маршруты из снапшота, содержимое экранов не сверено, дословных цитат не даю.

## ЗАЧЕМ
Снять страх установки: мастер генерирует «две команды» (первая скачивает установщик с собственного кластера по токену, интернет не нужен; вторая запускает установку), а кнопки «добавить объект мониторинга» в платформе нет: агент сам находит процессы и сервисы.
Вторая половина темы: где следить за парком (офлайн-агенты, отставшие версии, здоровье самих агентов).

## ЦИФРЫ
- Команды установки: две, обе генерирует мастер под платформу (точный вид: на экране мастера и в доке OneAgent on Linux).
- Экраны контроля парка: два (Deployment Status, OneAgent Health).
- Режим нового агента: страница OneAgent default mode (Тема 2); ключ командной строки сильнее общей настройки.

## ЕСЛИ→ТО
- ЕСЛИ хост появился, а трейсов по приложению нет → прикладные процессы (Java, .NET) не перезапущены после установки: глубокий мониторинг начинается после рестарта.
- ЕСЛИ свежепоставленный хост не появился в Deployment Status → проверить связность агент → ActiveGate и правильность токена, это первые две причины.
- ЕСЛИ сервисов от нового хоста не видно → трафика ещё не было: сервис рождается из запросов, ждать первых вызовов.
- ЕСЛИ в air-gapped ждут «автообновления из интернета» → его нет: сначала админ вручную вносит пакет в кластер, потом парк раскатывается сам.

## ЗАПАСНОЙ ПЛАН
Реальную установку не выполняю (как и оригинальный курс): показываю вход `/#deploy` и мастер до генерации команд; экран мастера после «Start installation» не сверен, деталей не обещаю.
Если мастер не открылся: рассказ по блокам входного экрана (agentless, synthetic, mobile, OpenKit, Install ActiveGate) и формула «две команды» словами.

## ВОПРОСЫ АУДИТОРИИ
- «Что нужно в нашем change management, чтобы выполнить две команды на боевом сервере?» Ответ на обсуждение: токен установки, окно работ, согласование владельца, план перезапуска прикладных процессов; сама техника занимает минуты.
- «Почему после установки нет кнопки „добавить сервис"?» Ответ: её нет в принципе: агент сам обнаруживает процессы и сервисы, список строится из увиденного трафика.
- «Откуда берётся установщик в закрытом контуре?» Ответ: с собственного кластера по токену; наружу первая команда не ходит.
