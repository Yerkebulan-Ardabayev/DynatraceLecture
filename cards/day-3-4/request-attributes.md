## ГДЕ
Настройка: Settings → Server-side service monitoring → Request attributes, классический route `/#settings/server/requestattributes` (сверено 2026-07-28: заголовок «Request attributes», кнопка «Define a new request attribute»).
Результат: Application Observability → Multidimensional Analysis (`/ui/diagnostictools`), готовый вид «Easy Trave User Request Attribute View1» (имя с опечаткой, так на демо-стенде).

## ЗАЧЕМ
Request attribute это пары ключ/значение на конкретном запросе: мост техника ↔ бизнес («покажи ошибки только по премиум-клиентам» одним фильтром).
Источники значения: данные web-запроса (заголовки, параметры), аргументы методов Java / .NET / PHP, OneAgent SDK. Дальше атрибут работает как измерение в MDA, в custom error rules и фильтрах запросов.

## ЦИФРЫ
- До 100 атрибутов на запрос; до 10 значений одного атрибута (дока shortlink/request-attributes).
- До 1 000 значений в расчётах (avg, sum, count, max); до 1 000 атрибутов на распределённый трейс.
- Хранение метрик «Requests and request attributes»: конфигурируется до 365 дней.

## ЕСЛИ→ТО
- ЕСЛИ бизнес просит разрез, которого нет в технике (тип клиента, канал) → завести request attribute на этот ключ, и разрез появится в MDA.
- ЕСЛИ атрибут захватывает персональные данные (номер счёта в параметре) → согласовать с безопасностью или не захватывать: правило «бизнес-ключи, не ПД».
- ЕСЛИ на демо нажать «Define a new request attribute» → не сохранится: «Missing permissions to create or edit request attributes»; на вашем Managed форма рабочая.
- ЕСЛИ список пуст, как на демо («No request attributes defined!») → показывать конструкцию формой без сохранения и результат готовым MDA-видом.

## ЗАПАСНОЙ ПЛАН
Экран показываю живьём (список пуст: это честно проговариваю дословными цитатами экрана), конструкцию: формой без сохранения, результат: готовым видом «Easy Trave User Request Attribute View1» в MDA.
Если вид в MDA не нашёлся: словами разобрать пример «атрибут = тип клиента, разрез ошибок по нему» и лимиты из доки.

## ВОПРОСЫ АУДИТОРИИ
- «Какой атрибут завести первым: клиент, канал, версия?» Ответ на обсуждение: тот, о котором бизнес спрашивает чаще всего; типовой победитель: тип клиента или канал (мобильный банк / веб / касса).
- «Это не то же самое, что тег?» Ответ: тег висит на сущности (сервисе, хосте), атрибут на каждом отдельном запросе; тег отвечает «что это за сервис», атрибут «что это за запрос».
- «Почему лимиты: 100 атрибутов, 10 значений?» Ответ: атрибуты пишутся на каждый запрос, это дорогая по хранению механика; лимиты защищают кластер, поэтому захватываем немногие осмысленные бизнес-ключи, а не всё подряд.
