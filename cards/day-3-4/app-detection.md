## ГДЕ
Пять связанных страниц Settings → Web and mobile monitoring → Web.
Application detection, route `/ui/settings/builtin:rum.web.app-detection`.
Beacon origins for CORS, route `/ui/settings/builtin:rum.web.beacon-domain-origins`.
Identify host names, route `/ui/settings/builtin:rum.host-headers`.
IP determination, route `/ui/settings/builtin:rum.ip-determination`.
Map IP addresses to locations, route `/ui/settings/builtin:rum.ip-mappings`.

## ЗАЧЕМ
OneAgent вставляет один RUM-сниппет во все HTML-ответы веб-сервера, поэтому данные нескольких приложений идут одним потоком.
Правила детекции разбирают этот поток на отдельные Applications по URL/host: без правил одно смешанное приложение, с правилами каждый сайт со своими метриками, SLO и alerting.
Остальные страницы обслуживают детекцию: host names и IP-заголовки за reverse-proxy, CORS для приёма beacon'ов, IP-mappings для локации.

## ЦИФРЫ
- Правила App detection матчатся по URL, оценка сверху вниз (срабатывает первое совпавшее и останавливает обработку), лимит до 1000 правил на окружение.
- Типовое применение App detection: 3-10 правил по числу разных публичных и внутренних веб-приложений (у вашего тенанта цифры могут быть другими).
- Beacon origins for CORS: до 20 правил на окружение; пустой список принимает beacons с любого origin, хотя бы одно правило отклоняет всё несовпадающее ответом 403 Forbidden.
- IP determination: за reverse-proxy/CDN IP клиента берётся из заголовков (X-Forwarded-For, X-Real-IP и аналоги) в заданном порядке, последний октет по умолчанию маскируется для приватности.
- Геолокация веб-приложений по умолчанию из MaxMind Geo2 database, обновляется с каждой поставкой Managed-релиза.
- Внутренние диапазоны (10.x, 192.168.x) в MaxMind отсутствуют, гео задают кастомными mapping (пример: 10.10.0.0/16 → офис 1, 10.20.0.0/16 → офис 2).

## ЕСЛИ→ТО
- ЕСЛИ приложение за reverse-proxy, а X-Forwarded-Host не добавлен в Identify host names → все страницы кажутся идущими с одного внутреннего домена прокси (nginx-internal.local), App detection не разложит трафик правильно.
- ЕСЛИ список Beacon origins пустой → endpoint принимает cross-origin beacons с любого домена; ЕСЛИ добавлено хотя бы одно правило → всё несовпадающее отклоняется ответом 403 Forbidden.
- ЕСЛИ за reverse-proxy/CDN не настроены заголовки IP determination → все клиенты кажутся с IP прокси, геолокация и анализ по странам не работают.
- ЕСЛИ два приложения не разделены правилами детекции → метрики смешиваются, отдельный SLO (например Availability клиентского портала ≥ 99.9%) задать нельзя, alerting profiles ловят проблемы чужого приложения.

## ВОПРОСЫ АУДИТОРИИ
- «Совпало не то правило, что делать?» Ответ: правила оцениваются сверху вниз, срабатывает первое совпавшее и останавливает обработку, поэтому порядок решает, а более узкие правила ставят выше.
- «Зачем отдельная страница Beacon origins, если приложение уже детектится?» Ответ: это про CORS-приём beacon'ов, когда они идут на другой домен (agentless или переключённый endpoint), пустой allowlist принимает всё, непустой отклоняет чужое ответом 403.
- «Почему все клиенты будто из одного места?» Ответ: за reverse-proxy IP берётся из заголовков в заданном порядке (X-Forwarded-For и аналоги), без настройки IP determination виден только IP прокси, а внутренние диапазоны в MaxMind отсутствуют и требуют кастомных mapping.
- «На сколько приложений разбить наш портал?» Ответ на обсуждение: по зонам ответственности (кто чинит, тот и видит своё приложение), а не «одно приложение на весь портал»: смешанные метрики это средняя температура; реально организации хватает нескольких правил, лимит 1000 на окружение практически не упирается.
