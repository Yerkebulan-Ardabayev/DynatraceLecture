# CONTENT_POLICY — конституция курса dt-crawler

Курс — для банков и госорганизаций **Казахстана** по Dynatrace **Managed** в **air-gapped** контуре. Этот документ фиксирует, что можно писать в `explanations/*.md`, а что нет. Любой будущий рерайт (свой или пользователя) сверяется с этим файлом. Автоматическая проверка — `scripts/quality_check.py`. Pre-build hook в `plan_html.py` блокирует сборку при `errors > 0`.

---

## 1. Приоритет №1 — фактологическая точность

Для Dynatrace Managed главное — **технические нюансы точны**: настройки, лимиты, overhead, retention, поведение фич, air-gapped-специфика. Это выше стиля, структуры и humanizer.

**Источники истины (в порядке приоритета):**

| Класс утверждения | Источник |
|---|---|
| UI (heading, button, путь в меню, URL) | `output/data/ui_elements.json` + `output/data/pages.jsonl` — captured с `guu84124.live.dynatrace.com` |
| Technical facts про Managed (overhead %, retention, лимиты, дефолты, поведение фич, air-gapped) | **`dtkb` skill** (личный FTS5-индекс Dynatrace docs) |
| Fallback tech-facts | `docs.dynatrace.com/managed/` через WebFetch |

**Инвентарь tech-claims** — `scripts/extract_tech_claims.py` вытаскивает все numeric-утверждения из `explanations/*.md`; результат в `tech_claims_verification.md` с колонками: claim / file:line / источник подтверждения / действие (подтверждён / смягчён / удалён).

## 2. Что ЗАПРЕЩЕНО

### 2.1 РФ-регуляторы и РФ-ОС (курс для РК)

- **ФСТЭК, Роскомнадзор, Роспотребнадзор** — удалить или заменить на «национальный регулятор / ЦАРКА / КИБ РК».
- **Astra Linux, Astra Linux Special Edition, РЕД ОС** (если не подтверждено заказчиком) — заменить на «сертифицированный Linux-дистрибутив».

**Было:** `госкомпания с требованиями ФСТЭК. Кластер на Astra Linux Special Edition.`
**Стало:** `госорганизация с требованиями национального регулятора. Кластер на сертифицированном Linux-дистрибутиве.`

### 2.2 Roadmap-даты

Dynatrace не публикует публичных дат релизов. Запрещены формулировки вида:

- «Grail в Managed запланирован на 2027 год»
- «DQL следом»
- «ожидается в 2026 году»

**Было:** `Grail в Managed запланирован на 2027 год, DQL следом.`
**Стало:** `Grail и DQL — часть SaaS-платформы. В публичных roadmap Dynatrace сроки их появления в Managed не зафиксированы.`

### 2.3 Marketing и sales battle cards

Курс обучает работе с платформой, не продаёт её. Запрещены:

- Субъективная лексика про конкурентов: «не вкладывается», «слабый APM», «выбирают чаще», «теряют трейс».
- Выдуманные метрики: «3-5 инженеров на поддержку Open Source», «конкуренты медленнее развиваются».
- Таблицы «Dynatrace vs AppDynamics/Splunk/Open Source» в обучающем материале — это battle card, не обучение.

**Исключения (допустимы):**

- Упоминание конкурента **как аналогии синтаксиса**: «DQL похож на Splunk SPL или Kusto» — ок, учебная параллель.
- Упоминание бренда **как производителя железа**, не конкурента APM: «коммутаторы Cisco, Juniper, Huawei» — ок.
- Упоминание **на миграционном проекте**: «заказчик мигрировал с AppDynamics на Dynatrace» — допустимо, если без оценочных сравнений и без выдуманных результатов.

### 2.4 Выдуманные success-stories

Конкретные цифры «до/после» без источника. Запрещены:

- «MTTR 60 → 15 минут», «алертов в 8 раз меньше»
- «800 серверов, 200 микросервисов, цена +60%»
- Любые «Результат:» с круглыми цифрами без PR-ссылки или имени кейса в Dynatrace Customer Stories.

**Допустимо:** архитектурный шаблон без результатов — «типовая инсталляция в банке: 2 × ActiveGate, 3 × Cluster Node, кластер на 500 hosts».

### 2.5 Support-инструкции

Курс не учит процессу эскалации. Запрещены:

- «обратиться в поддержку Dynatrace»
- «через интегратора»
- «открыть тикет в Mission Control»
- «помогает поддержке Dynatrace локализовать проблему»

**Допустимо:** упоминание **ITSM-интеграций** как функциональности («OneAgent может открыть тикет в Jira/ServiceNow через webhook»).

### 2.6 Unsourced numeric claims

Проценты overhead / CPU / памяти и rps-характеристики без источника. Каждое численное утверждение про **поведение Managed** должно быть:

- Либо подтверждено в `dtkb` / `docs.dynatrace.com/managed/` — с привязкой в `tech_claims_verification.md`.
- Либо смягчено («обычно невысокий», «сотни мегабайт», «заметной доли CPU не тратит»).
- Либо удалено.

**Было:** `до 5% CPU при 10000 rps на одном хосте.`
**Стало:** `при экстремальной нагрузке overhead может расти — точные цифры зависят от профиля трафика.`

## 3. Что ДОПУСТИМО

- **Generic-иллюстрации** с явной подписью «например», «типично», «обычно»: `если сервис обычно отвечает за 50 мс, а сейчас 400 мс — это аномалия`.
- **Цифры с captured-тенанта** (`Browse 618` / `Manage 77`) — но с оговоркой «у вашего тенанта цифры могут быть другими».
- **Аналогии синтаксиса / технологий** («DQL как Splunk SPL», «Managed как on-prem Kubernetes»).

---

## 4. Структурные правила курса

1. **Только русский язык.** Технические термины поясняются в скобках на русском при первом упоминании. НЕТ «the point is», «actually», «anyway», смешанному языку.
2. **Только Managed.** НЕ упоминать как активное: Grail, Notebooks, Workflows, Apps platform, DPS billing, Mission Control, AppSec в новом Apps-формате. Упоминать только чтобы объяснить: «это SaaS-функциональность, в Managed не включена».
3. **Для первой темы дня/курса — контекст → UI.** Шаблон `КАРТА → Что показать → ТЕОРИЯ` работает начиная со второй темы. Первая тема открывается вводным блоком теории (правило: `feedback_first_topic_context_before_ui.md`).
4. **Имена конкретных клиентов и банков отсутствуют в заголовках, текстах и примерах** — курс общий, не для одного клиента. В кейсах использовать обезличенные формулировки («банк», «крупный enterprise», «финансовая организация»).
5. **Не пересказывать UI-баннеры платформы** (`Try the new…`, `Leverage the flexibility…`, `Discover recent additions…`). Техсуть одной фразой без цитаты. Исключение: баннер с air-gapped-специфичной техникой — переписать собственными словами (правило: `feedback_no_ui_banners_in_narration.md`).
6. **DQL только SaaS.** В air-gapped Managed: Metrics Selector (Data Explorer Advanced mode), USQL (для сессий), search + фильтры UI (для логов). Не писать «DQL в Advanced mode Managed» (правило: `feedback_dql_only_saas.md`).

## 5. Allowlist

Если regex даёт ложное срабатывание, строку можно пометить inline-комментарием:

```md
Коммутаторы Cisco, Juniper, Huawei. <!-- qc:ignore=MARKETING -->
```

или полностью:

```md
Некоторые частные легитимные термины. <!-- qc:ignore -->
```

Используется редко — по умолчанию политика приоритетнее исключений.

## 6. Процесс проверки

1. После любой правки `explanations/*.md`: `python scripts/quality_check.py`.
2. Финиш-критерий: `✅ 0 errors`. Warnings — к просмотру, но не блокируют сборку.
3. Для numeric tech-claims: `python scripts/extract_tech_claims.py` → верификация через `dtkb` → обновить `tech_claims_verification.md`.
4. Pre-build hook в `plan_html.py`: `quality_check.py` вызывается перед сборкой. Если `errors > 0` — build fails.

Любой новый класс ошибок → добавить детектор в `scripts/quality_check.py` и запись в этот файл. Политика живёт в репозитории, не в чьей-то памяти.

## 7. Карточки лектора (v2 Presenter Edition)

Карточки `cards/<day>/<topic>.md` (по одной на каждую из 44 тем) сжимают explanation для окна докладчика v2. **Контракт:** карточка не вводит новых фактов, только сжимает проверенные; любая цифра карточки обязана присутствовать в explanation своей темы. Схема: YAML-шапка (`topic_id`, `day_id`, `timing_min`, `verified`) плюс блоки ГДЕ / ЗАЧЕМ / ЦИФРЫ / ЕСЛИ→ТО / ЗАПАСНОЙ ПЛАН / ВОПРОСЫ АУДИТОРИИ.

Проверка включается флагом (чтобы не трогать гейт v1, который остаётся про `explanations/`):

```bash
python scripts/quality_check.py --cards
```

| Детектор | Severity | Что ловит |
|---|---|---|
| `CARD_MISSING` | warn | тема без карточки (не блокирует, пока идёт наполнение) |
| `CARD_EMDASH` | error | длинное тире `—` в карточке |
| `CARD_BANNED_CATEGORY` | error | те же запрещённые категории (§2), применённые к тексту карточки |
| `CARD_UNSOURCED_NUMBER` | error | цифра-токен карточки, которого нет в explanation той же темы |

`CARD_UNSOURCED_NUMBER` сверяет цифра-токены (`\d+(?:[.,]\d+)?`): факт, которого в explanation нет как цифры, в карточке пишется словом («три типа»), а не цифрой. Сборка `--v2` (`plan_html.py --v2`) вызывает `quality_check --cards` автоматически; дефолтная сборка v1 запускает чекер без `--cards`, поэтому его поведение не меняется.
